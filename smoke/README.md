# Reusable smoke scenarios

Scenarios for the harness documented in CLAUDE.md (`CLEW_SMOKE=/out.png
CLEW_SMOKE_SCRIPT=<scenario> CLEW_SMOKE_VAULT=<vault> electron .`) —
committed so sessions stop rewriting them. Always pass
`CLEW_SMOKE_VAULT`; add `CLEW_SMOKE_LOG=1` to see each scenario's
`smoke-*:` assertion lines; `CLEW_USER_DATA=<dir>` isolates app settings
(fresh-install simulation; HOME alone does not isolate Electron on
macOS). Under `CLEW_SMOKE` settings are never persisted at all
(settings.js#save no-ops), so scenarios cannot leak vaults or setting
flips into the user's real app state. Long runs (anything booting
LibreOffice) belong in the background with output to a file.

Helpers, plain node (no Electron):

- `gen-big-vault.mjs <dir> [notes]` — deterministic synthetic vault
  (default 5000 notes: frontmatter, wikilinks, tasks, plus `Dashboard.md`
  and `Board.md` query fences). Note folders are RANDOM — touch a path
  you looked up, not one you guessed.
- `index-bench.mjs <vault>` — cold vs warm Indexer build, timed.
- `make-figures-vault.mjs <dir>` — the figures fixture: `Figures.md`
  (every TikZ/MetaPost syntax, the ```latex and ```tex documents, the
  `show=` modes, graph drawing, a calligraphy stroke and a mermaid
  control), `Highlight.md` (one fence per editor grammar, fitting one
  viewport) and `Edit.md` (one fence and one line of prose, which the
  edit scenario rewrites).
- `make-global-plugin.mjs <dir> [--enabled]` — the global-plugin fixture:
  an isolated userData holding one installed plugin (all three surfaces)
  plus a vault using its fence. Without `--enabled` the vault opts out,
  which is how the trust gate is checked; with it, the state after a
  restart. Its header carries the full invocation.

Baseline on the owner's machine (2026-09-02, M-series, 5003 notes):
cold index 412ms, warm 64ms; search 1–6ms; dashboard first render ~1s;
save→dashboard-rerender ~1.5s (incl. the 600ms query debounce);
~800MB total across processes with a dashboard open.
