# Reusable smoke scenarios

Scenarios for the harness documented in CLAUDE.md (`CLEW_SMOKE=/out.png
CLEW_SMOKE_SCRIPT=<scenario> CLEW_SMOKE_VAULT=<vault> electron .`) —
committed so sessions stop rewriting them. Always pass
`CLEW_SMOKE_VAULT`; add `CLEW_SMOKE_LOG=1` to see each scenario's
`smoke-*:` assertion lines; `CLEW_USER_DATA=<dir>` isolates app settings
(fresh-install simulation; HOME alone does not isolate Electron on
macOS). Long runs (anything booting LibreOffice) belong in the
background with output to a file.

| Scenario | What it drives | Vault it expects |
| --- | --- | --- |
| `atomic-save-scenario.js` | Types into `Test.md` via the editor pool, waits out the 1s auto-save, logs the dirty flag. Verify by reading the vault afterwards (content landed, no `.clew-tmp` litter). | any, containing `Test.md` |
| `history-scenario.js` | Two edits + auto-saves to build history snapshots, then opens the history modal on the oldest. Pair with vault-settings `history: { "minIntervalMinutes": 0 }` so every save snapshots. | any, containing `Test.md` |
| `history-restore-scenario.js` | Second run over the same vault: opens the modal, restores the oldest snapshot through its buttons, logs that the editor reloaded. | the vault the run above left |
| `demo-click-scenario.js` | First-run flow: clicks “Explore the demo vault” on the welcome screen, waits for the vault to open. Run the PACKAGED app with a fresh `CLEW_USER_DATA` and no `CLEW_SMOKE_VAULT`; delete `~/Documents/Clew Demo Vault` before/after. | none (welcome screen) |
| `office-download-scenario.js` | Downloads the office engine over the real CDN into userData, then opens `Test Document.docx` and waits out the LibreOffice boot. Packaged app + fresh `CLEW_USER_DATA`; takes minutes. | any, containing `Test Document.docx` |
| `big-vault-scenario.js` | Stress numbers: search latency, query-dashboard render, and the save→requery round-trip. First render logs TIMEOUT when served from a warm cache (no render event fires on cache hits) — delete the vault's `.clew/` for a cold run. | one generated by `gen-big-vault.mjs` |
| `watch-diag-scenario.js` | Writes one existing note through NOTE_WRITE and logs exactly which watcher events came back (`change` vs `tree`) — the atomic-write/chokidar diagnostic. | one generated by `gen-big-vault.mjs` |

Helpers, plain node (no Electron):

- `gen-big-vault.mjs <dir> [notes]` — deterministic synthetic vault
  (default 5000 notes: frontmatter, wikilinks, tasks, plus `Dashboard.md`
  and `Board.md` query fences). Note folders are RANDOM — touch a path
  you looked up, not one you guessed.
- `index-bench.mjs <vault>` — cold vs warm Indexer build, timed.

Baseline on the owner's machine (2026-09-02, M-series, 5003 notes):
cold index 412ms, warm 64ms; search 1–6ms; dashboard first render ~1s;
save→dashboard-rerender ~1.5s (incl. the 600ms query debounce);
~800MB total across processes with a dashboard open.
