# Reusable smoke scenarios

Scenarios for the harness documented in CLAUDE.md (`CLEW_SMOKE=/out.png
CLEW_SMOKE_SCRIPT=<scenario> CLEW_SMOKE_VAULT=<vault> electron .`) —
committed so sessions stop rewriting them. Always pass
`CLEW_SMOKE_VAULT`; add `CLEW_SMOKE_LOG=1` to see each scenario's
`smoke-*:` assertion lines; `CLEW_USER_DATA=<dir>` isolates app settings
(fresh-install simulation; HOME alone does not isolate Electron on
macOS). Under `CLEW_SMOKE` settings are never persisted at all
(settings.js#save no-ops), so scenarios cannot leak vaults or setting
flips into the user's real app state. Long runs (anything booting
LibreOffice) belong in the background with output to a file.

| Scenario | What it drives | Vault it expects |
| --- | --- | --- |
| `atomic-save-scenario.js` | Types into `Test.md` via the editor pool, waits out the 1s auto-save, logs the dirty flag. Verify by reading the vault afterwards (content landed, no `.clew-tmp` litter). | any, containing `Test.md` |
| `history-scenario.js` | Two edits + auto-saves to build history snapshots, then opens the history modal on the oldest. Pair with vault-settings `history: { "minIntervalMinutes": 0 }` so every save snapshots. | any, containing `Test.md` |
| `history-restore-scenario.js` | Second run over the same vault: opens the modal, restores the oldest snapshot through its buttons, logs that the editor reloaded. | the vault the run above left |
| `demo-click-scenario.js` | First-run flow: clicks “Explore the demo vault” on the welcome screen, waits for the vault to open. Run the PACKAGED app with a fresh `CLEW_USER_DATA` and no `CLEW_SMOKE_VAULT`; delete `~/Documents/Clew Demo Vault` before/after. | none (welcome screen) |
| `office-download-scenario.js` | Downloads the office engine over the real CDN into userData, then opens `Test Document.docx` and waits out the LibreOffice boot. Packaged app + fresh `CLEW_USER_DATA`; takes minutes. | any, containing `Test Document.docx` |
| `big-vault-scenario.js` | Stress numbers: search latency, query-dashboard render, and the save→requery round-trip. First render logs TIMEOUT when served from a warm cache (no render event fires on cache hits) — delete the vault's `.clew/` for a cold run. | one generated by `gen-big-vault.mjs` |
| `watch-diag-scenario.js` | Writes one existing note through NOTE_WRITE and logs exactly which watcher events came back (`change` vs `tree`) — the atomic-write/chokidar diagnostic. | one generated by `gen-big-vault.mjs` |
| `reading-scroll-scenario.js` | Reading→source position carry-over: scrolls the preview the way a reader does (a `scroll-to-line` posted straight into the iframe, which leaves the host's suppressor idle), flips to source, and logs where the editor landed. Logs a second phase for the round trip that must change nothing. Assert `landed`/`top` = the scrolled line, and `roundtrip` = `parked` line AND column. | any, containing a `Long.md` far taller than the window |
| `folder-state-scenario.js` + `folder-state-restore-scenario.js` | File-explorer disclosure state across a restart: run 1 closes two folders, run 2 (same vault) asserts `restored-rows` equals run 1's `rows-after-click`, then renames a closed folder through its real context menu and watches the closed children follow. Run 2 leaves the vault renamed — regenerate the fixture (its header has the one-liner) before repeating. | one from that header's `mkdir` recipe |
| `embed-refresh-scenario.js` + `embed-refresh-frame.js` | A transclusion chain going stale: opens Grandparent (which embeds Parent, which embeds Child), rewrites Child, and asserts the open preview picks it up. `has-UPDATED=true` / `has-ORIGINAL=false`; both were reversed before embed invalidation existed. | one from that header's `printf` recipe |
| `embed-collapse-scenario.js` + `embed-collapse-frame.js` | Foldable embeds: renders a plain / `\|collapsed` / `\|Reading list\|open` trio, reports tag + open + line + title for each, then clicks the closed one's summary. The real assertion is on disk — `Parent.md` line 9 must have become `![[Child\|open]]` while lines 5 and 13 stay put. | one from that header's `printf` recipe |
| `print-pdf-scenario.js` | "Export as PDF (reading view)" over a note with maths, mermaid, code, a table, a callout and two embeds — the asynchronous things a print can catch half-drawn. Uses EXPORT_NOTE's `outFile` bypass so no save dialog blocks the run; its header carries the on-disk checks (page count, A4 MediaBox, pdftotext, rasterize page 1). | any, containing that `Print Me.md` |
| `embed-chrome-scenario.js` + `embed-chrome-frame.js` | Embed frame levels (`\|quiet`, `\|bare`): reports the computed stripe/box/radius/title for each, then the seam test — a bare embed's gaps above and below must EQUAL the same content written inline (20px / 16px in the reference fixture). | one from that header's `printf` recipe |
| `global-plugin-scenario.js` + `global-plugin-frame.js` | A globally installed plugin, all three surfaces: discovered with `scope: global`, engine fence rendered, preview script served from `__clew_plugin_file__` with a working sibling fetch, app command registered. Needs `CLEW_USER_DATA=<dir>/userdata` so the install is isolated. | one from `make-global-plugin.mjs` |

Helpers, plain node (no Electron):

- `gen-big-vault.mjs <dir> [notes]` — deterministic synthetic vault
  (default 5000 notes: frontmatter, wikilinks, tasks, plus `Dashboard.md`
  and `Board.md` query fences). Note folders are RANDOM — touch a path
  you looked up, not one you guessed.
- `index-bench.mjs <vault>` — cold vs warm Indexer build, timed.
- `make-global-plugin.mjs <dir> [--enabled]` — the global-plugin fixture:
  an isolated userData holding one installed plugin (all three surfaces)
  plus a vault using its fence. Without `--enabled` the vault opts out,
  which is how the trust gate is checked; with it, the state after a
  restart. Its header carries the full invocation.

Baseline on the owner's machine (2026-09-02, M-series, 5003 notes):
cold index 412ms, warm 64ms; search 1–6ms; dashboard first render ~1s;
save→dashboard-rerender ~1.5s (incl. the 600ms query debounce);
~800MB total across processes with a dashboard open.
